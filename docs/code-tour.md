# 源码导读

## 1. Modbus RTU：从输入字节到响应报文

阅读 [modbus_process()](../src/protocol/modbus.c)，关注以下顺序：

1. 从传输层取得新数据，检查累积缓冲区剩余容量。
2. 根据功能码和头部字段判断预期帧长度。
3. 校验 CRC，随后检查从站地址并分发请求。
4. 检查数量与寄存器范围，再执行读写或构造异常响应。
5. 保留已收到的后续报文，在下一次轮询中继续处理。

公开的保持寄存器表由协议模块单独管理，演示与测试使用合成数据。`0x03` 实现读保持寄存器，`0x06` 实现写单寄存器，`0x10` 实现写多寄存器。广播写入执行后保持静默。

## 2. RS485：DMA、UART 与收发方向

阅读 [rs485_send() 与中断处理](../ports/n32/rs485.c)。发送路径先检查忙状态、复制数据并拉起方向引脚；DMA 中断再开启 UART 发送完成事件，最终由 UART 事件释放方向引脚。

接收路径采用循环 DMA，空闲事件记录 DMA 写指针，前台接口读取当前有效段。主机测试通过内存适配器覆盖协议输入输出；实际 UART 空闲时序、DMA 回绕与总线电气行为需要目标板测量。

## 3. EtherCAT PDI：可定位的访问错误

阅读 [qspi_pdi_record_error()](../ports/n32/qspi.c)。诊断结构保存访问方向、地址、长度、错误类型和累计次数，等待操作使用有界退出条件。相关字段用于 MCU 与从站控制器之间的 PDI 诊断。

EtherCAT 从站协议栈、对象字典和驱动模式处理的详细实现已从公开包移除，架构文档保留集成关系。

## 4. EEPROM：页写入与错误收尾

阅读 [eeprom_write()](../ports/n32/eeprom.c) 及内部页写入函数，关注页剩余空间、有效地址范围、写周期等待，以及 STOP、ACK 和外设恢复的配合。

文件还保留原工程的测试接口，硬件接入时应先阅读其写入与恢复行为。主机演示仅调用内存传输和协议模块。

## 5. CAN：统一帧结构

阅读 [can_send() / can_read()](../ports/n32/can.c)，观察标准帧与扩展帧 ID、远程帧标志和 DLC 的转换。接收回调由硬件 FIFO 中断触发。

## 6. 测试：复现协议行为

[test_protocol.c](../tests/test_protocol.c) 验证已知 CRC 向量、正常读写、最大数量、越界、广播、错误地址、错误 CRC、分片、连续帧及发送忙状态，并执行确定性异常输入检查。

[test_redacted_motor.c](../tests/test_redacted_motor.c) 验证初始化、有效命令、极值命令与空指针调用后，电机输出始终关闭。
